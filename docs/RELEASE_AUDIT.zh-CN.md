# O-Attack 发布整理核对记录

本整理包保留攻击、受害模型评估、GLM-5 评分完整流程；包含完整 1,000 对图像、原 G3 的 100 对默认子集及原先生成的 100 张 G3 对抗样本。只保留一个攻击配置：`configs/attack/default.yaml`。论文题目、作者、项目页与引用来自现有 GitHub 介绍仓库。

## 数据与示例

| 内容 | 数量 | 检查结果 |
|---|---:|---|
| 完整基准 | 1,000 对，ID 0–999 | 源/目标 ID 一一对应；图像可解码；每张有 5 条非空描述 |
| 默认 G3 子集 | 100 对，ID 0–99 | 图像字节与完整数据中的对应 ID 相同；保留原子集的描述文本 |
| 描述文本 | 完整数据 10,000 条；默认子集 1,000 条 | 保留两组原始描述；每组 ID 无重复、无遗漏 |
| G3 对抗示例 | 100 张 224×224 RGB PNG | 原样复制；生成记录与默认 G3 优化参数一致；最大像素扰动 16 |

完整数据是在原项目的另一份实现目录中找到的；指定 release 目录只有 100 对。两套数据的前 100 个图像 ID 相同、图像文件相同，但源和目标各 100 条描述条目全部不同，因此不能直接用完整目录的前 100 项替换原最佳实验子集。发布包分别保留两个数据入口，默认仍使用原 100 对。

数据文件 SHA-256、配对和顺序见 `data/manifest.json` 与 `data/full_manifest.json`。原实现按文件名的字典序加载图像，例如 `0, 1, 10, 100, …`，不是数值排序；`sample_start` 是该顺序中的位置。运行完整数据时需同时切换源图像、目标图像与两个描述路径，具体命令见主 README。

示例样本来自原始 G3 最佳结果的合并目录。已核对合并图像与各分块原输出的 SHA-256 相同，并核对四个生成日志的源/目标 ID、300 步、ε=16、种子、层数和 dropout 设置。四次运行分别处理字典序位置 0、25、50、75 起的 25 对，每次重置 seed=2023。因此一次性运行 100 对时，后续随机序列会不同；示例说明保留了原分块命令，不承诺跨硬件逐字节复现。

像素扰动检查使用攻击实际的双三次缩放与 224×224 中心裁剪，对比处理后的源图像与保存的对抗 PNG。全部 100 张满足 L∞≤16（[0,255] 像素单位）。这批历史示例没有重新生成或压缩。

## 默认最佳配置

seed=2023，默认 100 对，batch=1；300 次 Adam 更新，学习率 1.0，ε=16/255；10 个源图像裁剪，scale=[0.55,0.95]，目标裁剪 scale=[0.9,1.0]。三个代理为 LAION CLIP ViT-G/14、OpenAI CLIP ViT-B/16、ViT-B/32。

G/14 视觉/文本末层数为 15/5，dropout 上限随步数由 0.10 增至 0.15；B/16 与 B/32 为 4/2，上限由 0.05 增至 0.10。具体概率从 0 至该步上限均匀采样。视觉和文本方差权重均为 1，使用原来的均值减方差目标。

## 代码处理

核心攻击 `oattack/attacks.py`、裁剪逻辑 `oattack/augmentations.py`、多代理特征/损失实现 `oattack/models/base.py` 和工具 `oattack/utils.py` 与原 release 逐字节相同，保留原优化过程。

整理修正集中在可运行性和结果完整性：

- 移除原服务器的模型、Conda 与数据绝对路径，使用项目相对路径、Hugging Face 模型 ID 或显式环境变量；三个 CLIP 权重固定为原缓存版本。首次运行可下载，离线模式需主动启用。
- 检查源/目标 ID 和顺序，拒绝重复、缺失或超范围采样；修复 JPEG 目标子集缓存和旧文件残留。
- API-only 评估不查询 GPU；空输出和推理错误记录后返回失败状态，避免静默遗漏。
- 评估缓存核对输入文件内容、模型、提示词和 token 限制，避免替换输入后误用旧描述。
- 评分保留全部配对和失败记录；ASR 为分数严格大于 0.5 的数量除以全部配对数量，失败样本仍计入分母；`ratio_ge_*` 单独表示大于等于阈值。
- 评分断点续跑只复用描述文本、judge 模型、API 端点及 reasoning 设置一致的成功记录；命令行子进程通过环境变量获取 API key。
- 修复 DeepSeek-VL2 与 InternVL 提示词中原来的字面 `\\n`，改为图像标记后的实际换行；Grok 默认适配器与论文中的 4.3 版本一致。

删除消融配置、旧脚本、未选用的代理/受害模型适配器、备份文件、实验日志、模型权重和凭据。保留论文中的 24 个受害模型入口及单一 GLM-5 judge。现有 `docs/` 项目网站和资源一并保留。

## 已完成的验证

1. 对完整 1,000 对、默认 100 对及 100 张对抗示例做文件哈希、可解码、ID、描述、配置与扰动检查。
2. 回归测试覆盖实际梯度更新与像素边界、完整数据加载、错配拒绝、目标子集重建、API-only 调度、缓存失效、评分阈值和失败计数。
3. 在本地回环 HTTP 服务上实际走通图像上传、描述推理、GLM 格式评分、JSON/CSV 汇总以及断点续跑；改变一个描述后只重新评分该配对。此测试没有调用付费 API。
4. Linux/CUDA 上用三个真实 CLIP 代理完成单对图像的默认 300 步攻击：301 条指标记录（300 步加最终记录）全部为有限值；输出 224×224，最大像素差为 16；用时约 188 秒。测试输出与发布示例分开，发布包只提供原始历史 100 张示例。
5. 从空 Python 3.10 虚拟环境安装主依赖，`pip check` 无冲突，16 项回归测试全部通过；三个真实 CLIP 代理再完成单图 3 步运行检查，保存图像的最大像素差为 3。
6. DeepSeek-VL2-tiny 与 InternVL3.5-8B 在原各自依赖环境中对示例 `0.png` 完成真实推理，均得到非空描述，失败数为 0。此处验证修正后的适配器；未声称验证全部本地模型的全新环境。
7. 三个 shell 入口从项目外目录启动 `--help` 成功，检查发布文本中的本机/服务器私有路径与 API key；未发现遗留值。

结构化验证记录见 `docs/validation.json`。具体安装与本地模型核验范围以该文件为准。

## 发布说明与验证范围

本次没有重新生成全部 1,000 张对抗图像，也没有重跑论文的 24 模型完整结果表或调用真实商业模型/judge API。提供的 100 张示例是历史最佳 G3 输出。API ID 沿用原实验记录；供应商当前可用性、计费及输出随时间变化，本次没有做在线推理验证。macOS 可保存、阅读代码，GPU 运行验证在 Linux/CUDA 完成，未验证 Apple MPS。

主依赖来自原攻击环境；三个特殊本地模型的版本分别记录在 `requirements/`。没有复制原 Conda 的所有包，以避免把历史实验环境中的无关依赖冲突带入发布包。DeepSeek 的 xformers 选用与 torch 2.0.1 匹配且满足其上游最低要求的 0.0.21。特殊模型完整环境的全新安装仍需分别验证。

原项目记录/论文说明源图像来自 NIPS 2017 Adversarial Learning Development Set、目标来自 MS-COCO validation，每张 5 条 LLM 描述。当前文件没有完整保留上游图像 ID 映射、抽样种子、生成描述的具体模型版本/提示词及再分发条款。现有 GitHub 仓库也没有软件许可证。本整理没有代作者选择许可证或补写不存在的信息；公开发布前应由作者补齐软件许可证、图像再分发说明及描述生成方法。

整理过程没有修改原服务器的代码、数据和实验结果。验证记录对应整理完成时的检查；发布版本以本仓库提交历史为准。
